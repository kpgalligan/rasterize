# core/CLAUDE.md — Rust core rules

Applies to everything under `core/`. Build commands, the FFI three-file lockstep, and cross-boundary pixel conventions are in the root CLAUDE.md.

## Module map

- `lib.rs` — module declarations and re-exports only. No implementation code.
- `rz_image.rs` — flat `RzImage`, format sniffing, file open/save/encode, and `from_rgba` (the in-memory twin of `open`, for pixels only the host can decode). (Named `rz_image`, not `image`, to avoid ambiguity with the `image` crate.)
- `doc.rs` — layer model, compositing/projection, document ops, layer masks. **Full — no new concerns.** A new feature area gets a new module. A styled layer's compositing is routed out to `style_composite.rs`; `doc.rs` only wires it (`CompositeEnv`, `merge_extent`).
- `blend.rs` — `BlendMode` + all blend math, the shared source-over/erase pixel primitives, `LUMA_*` constants.
- `rzdc.rs` — the native `.rz` file format. The doc comment on `encode_native` **is** the format spec.
- `psd.rs` — PSD import.
- `doc_select.rs` / `doc_transform.rs` — selections/fill/gradient and mask morphology; free transform.
- `poisson.rs` — the ONE membrane (Poisson) solver every healing op shares: free functions over window-sized buffers, the correction form `Δũ = 0` with `ũ|∂Ω = dest − source`, red-black multigrid (a cascade for the initial guess, then V(2,2) cycles), and the one classification rule stated on `Region`. Each cycle's coarse-grid correction is applied at the step length that minimizes the error's energy, which is what makes the method safe on a region whose boundary is mostly zero-flux — a fixed right-hand-side scale diverged there — and the cycle count is a scheduled minimum plus as many more as the MEASURED residual asks for, to a hard ceiling: a fixed count is a cost bound, never a convergence guarantee. Its module doc carries the measured accuracy/cost table over six geometries (Dirichlet and zero-flux alike), the divergence it replaced, and the reasons the plain cascade and a reduced-resolution solve were both rejected.
- `doc_heal.rs` — healing on the document: `heal_layer` (the Healing Brush and the Patch tool, driven by the SAME premultiplied overlay `rz_doc_painting_layer` takes), `heal_window_into_pixels` — the one write-back the inpainters share, writing into a single layer buffer so a many-part edit pays one clone — and `heal_window_into_layer`, that same call for the preview's one-layer temp document. Owns the 4-connected `components` walk the whole healing family splits its coverage with, and solves each component in its own window; the write weight is a hard cut at the coverage contour (Content-Aware Fill's soft selection bytes are the one exception), so no pixel ever receives an unsolved source. Two caps, both measured before anything is healed: `MAX_SOLVE_WINDOW_PIXELS` on one component's window (memory) and `MAX_HEAL_PLAN_PIXELS` on every component's window summed (the CALL's time — a stroke landing in many places pays a full pass per place).
- `doc_inpaint.rs` — content-aware inpainting on the document: spot healing (the footprint is the hole) and Content-Aware Fill (the selection is the hole), one pipeline per connected component — window, sampling ring, PatchMatch, then `doc_heal::heal_window_into_pixels`. Owns the caps (`MAX_INPAINT_HOLE_PIXELS`, `MAX_INPAINT_TARGET_PIXELS`, `MAX_INPAINT_PLAN_PIXELS`), which bound the whole CALL and not one component of it, and their refusal sentences — one per cap per `Caller`, because a spot-heal stroke has neither the selection nor the ring a fill's wording names; the two starved-neighbourhood refusals are told apart the same way (nothing to sample from at all, versus a band of real picture narrower than one source patch, which is the common case and used to be reported as the other); `Caller` also decides the hole's coverage threshold, since a selection's feathered ramp must be filled and faded while a brush dab is cut hard at 128. Its module doc carries the measured wall times and the cost model they support (what costs is the region DILATED by its ring plus the boxes its parts sit in — never the selected count). `inpaint_plan.rs` sizes every component and fits the whole call's rings BEFORE any of it runs, over TWO ladders: a cheap one from the bounding boxes alone, so a dust selection is refused in milliseconds rather than paying a distance transform per speck, then the exact one, whose windows are sized from the ring the narrowing settled on rather than the one the caller asked for. `inpaint_em.rs` is the pyramid/EM driver, `inpaint_preview.rs` everything the `preview` flag needs (reduce, solve small, upsample — the reduction is chosen from the whole call's WINDOWS, the quantity that drives cost, and a part cap bounds the parts a preview will fill, because a small part cannot be reduced at all).
- `patchmatch.rs` / `patchmatch_nnf.rs` — the ONE PatchMatch (Barnes et al.) search, masked pyramid and Wexler vote, and the sparse nearest-neighbour field with its propagation/random-search sweep. Every parameter and its reason — patch size, level count, iterations, the search-radius schedule, the ring widening, why the vote is never winner-take-all — is documented once, in `patchmatch`'s module doc.
- `doc_redeye.rs` — red-eye: red DOMINANCE (the ratio `R/((G+B)/2)` gated by HSV saturation and hue, not `R > G`) inside a canvas rect, a component gate against the rect's shorter side, and the neutralize-then-darken correction. Its module doc holds the fifteen-colour measured table that is the proof.
- `rng.rs` — `SplitMix64`, the crate's ONE PRNG. It was private to `ops_filters.rs` until the inpainter needed the same generator; shared code has exactly one home, so it moved here and `ops_filters` uses it (the noise filter's bytes are unchanged).
- `icc.rs` / `icc_transform.rs` / `icc_builtin.rs` — ICC v2/v4 RGB matrix-TRC parsing and the five-way inspect (a profile whose CLASS is a device link, an abstract transform or a named-colour list is refused with Gray/CMYK/Lab, not kept); the curve model, the combined matrix and the 8-bit transform (a forward-threshold encode — there is no curve inverter in this crate, and adding one is a regression); the two built-in profile blobs this build writes.
- `metadata.rs` / `metadata_write.rs` / `metadata_xmp.rs` — the ONE JPEG/PNG container walk (EXIF/XMP/IPTC/ppi in) and the shared TIFF-stream reader; the segment and chunk builders, the streaming injector, the in-place EXIF normalizer (orientation reset, resolution — corrected, else the packet is refused whole, since IFD0 outranks the container density in every reader — colour-space and dimension tags, IFD1 unlinked) and the 8BIM filter (out); and the XMP packet's own copies of the orientation and resolution, rewritten as text (an XMP packet has no internal offsets, which is why it may be resized and an IFD may not).
- `doc_color.rs` — assign vs convert, the working-space adoption, the resolution, the metadata packets, the per-format capability table, and the document-level image save.
- `ops.rs` / `ops_filters.rs` — flat-image ops and filters (`pub(crate)`, pure, clone-then-mutate).
- `adjust.rs` — the adjustment-layer interpreter; its module doc holds the JSON schema table for every recognized `meta` op. Layer `meta` is otherwise an opaque blob the core never interprets.
- `agent.rs` — embedded MCP server (streamable HTTP, tools-only, stateless). **Generic** — knows nothing about images; the host registers the catalog and a callback.
- `assistant.rs` — Anthropic Messages API tool loop (`ureq`, non-streaming; `api_base` is the provider seam), cancellation at tool/API boundaries, image pruning of old canvas renders.
- `style.rs` — layer styles: `LayerStyle` (the identity rule, `pad`, Scale Effects), `scaled_style`/`quad_mean_scale`, and the `impl RzDocument` block (`set_layer_style`, `set_global_light`); its module doc IS the style JSON schema table (the `adjust.rs` pattern — the header's "Layer styles" section points there). Re-exports every model type, so `style::` stays the one public path.
- `style_model.rs` / `style_effects.rs` — the model's value types (global light, Blend If, gradient fill, the enums, `Strictness`) and the nine effect structs with `EffectKind`/`Effect` and each effect's plane reach.
- `style_json.rs` / `style_json_write.rs` / `style_names.rs` — the ONE strict/lenient parser (with the clamp table and the four-decimal quantization), the canonical writer, and the name tables both read.
- `style_render.rs` — the padded shape plane (with sub-planes), the ONE blur (multi-level downsampled above sigma 3) / dilate / erode / shift primitives, `blur_reach`, and the per-effect dispatch; `style_gradient.rs` the ONE gradient box / sampler / colour. `style_cache.rs` — the per-style rendered-plane cache inside each `Arc<LayerStyle>`: pointer keys, the shape-equality refresh, the incremental sub-plane re-render for a brush tick, and the hand-over from a replaced style (`inherit_planes`); `style_reuse.rs` — which effect planes a new style can keep (`same_planes`) and how they take its colours (`restamp`), a mirror pair.
- `style_composite.rs` — the styled-layer compositing path `doc.rs` routes to: the Below / pixels / Interior order, Blend If, the layer-opacity package model, Merge Down's extent, and the ONE place a style's AUTHORED sRGB colour converts into the document's space (downstream of the plane cache, so a profile change invalidates nothing and the stored JSON is never rewritten).
- `style_fx_*.rs` / `style_blend_if.rs` — one effect each (drop shadow, inner shadow, outer glow, inner glow, stroke, color overlay, gradient overlay, bevel/emboss, satin) and the Blend If weight; each is a pure function of the shape and must stay local to its reach (the sub-plane re-render relies on it).
- `ffi.rs` / `ffi_doc.rs` / `ffi_filters.rs` / `ffi_agent.rs` / `ffi_assistant.rs` / `ffi_style.rs` / `ffi_color.rs` / `ffi_heal.rs` — thin shims only; shared plumbing lives in `ffi_util.rs`, never copy-pasted.

## Rules

**Modules and size.** New feature area = new module with its own `impl RzDocument` block (the `doc_select`/`doc_transform` pattern). Soft cap ~600 lines; needing a new `// ---- name --` banner section is the signal to split into a module instead. Every module keeps a `//!` doc; numeric/algorithmic choices get prose "why" comments (see `EXACT_EPSILON` in `doc_transform.rs` for the bar).

**One implementation per algorithm.** Before writing pixel math, find the existing implementation and route through it. If a duplicate is genuinely required (e.g. an offset-mapped variant), its comment must name the master copy. Shared constants have exactly one home (`LUMA_*` in `blend.rs`; `MAX_PIXELS` in `doc.rs`; RZDC caps in `rzdc.rs`).

**Purity.** Document/image ops take `&self` and return a new value — internally clone-then-mutate; `Arc`-shared pixels make it cheap. In-place mutation is allowed only for caller-owned mask buffers (the `rz_selection_*` family) and must be called out in the doc comment. An op that would change nothing returns `None`, never an identical copy — an identical copy registers a phantom undo step in the app.

**Errors.** Two tiers, no error enum: `Option<T>` = domain refusal, with the reason documented in the doc comment; `Result<T, String>` = I/O/decode/parse, lowercase message embedding the path (`format!("failed to read {path}: {e}")`). No input may panic — corrupt files return `Err`. FFI mapping: `None` → NULL/0/false; `Err` → `set_err(err_out, …)`; caught panic → `"internal error: <what>"` (long form, everywhere).

**FFI exports.** Every export: `#[no_mangle] pub unsafe extern "C"`, a `///` comment restating the header contract, a `/// # Safety` paragraph, NULL tolerance first, narrow `unsafe {}` blocks. Route through the shared helpers (`pure_op` / `doc_op` / `doc_get` / `ffi_util`) — a freshly hand-rolled `catch_unwind` is a review flag. Slice lengths are always recomputed from the core's own dimensions before `from_raw_parts`, never trusted from the caller. Export names mirror the Rust method exactly (`rz_doc_add_mask` ↔ `add_mask`); new ops use imperative names (`crop`, `add_mask`), not the older participial style. Don't rename existing exports.

**Format changes.** Any change to persisted layer/document state bumps `RZDC_VERSION`; the reader must keep accepting every prior version; the writer enforces the reader's caps so every file it produces can be read back. New recognized `meta` shapes update the schema table in `adjust.rs`'s module doc.

**Tests.** All tests are black-box in `core/tests/` (no `#[cfg(test)]` in `src/`), exercised **through the FFI** wherever possible, and verified against independently written oracles (e.g. the W3C reference blend) — never golden images. Shared helpers live in `tests/common/`; new feature area = new test file (don't grow an existing one past ~1500 lines). Every new export gets at least one test plus inclusion in the null-safety sweep. ImageMagick-dependent fixtures must skip gracefully when it's absent. Finish Rust work with `cargo fmt` and a clean `make lint`.
