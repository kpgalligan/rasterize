# app/CLAUDE.md — Swift app rules

Applies to everything under `app/`. Build/verification commands and the FFI lockstep are in the root CLAUDE.md.

## File map

- `RasterCore.swift` — the **only** home for `rz_*` function calls: handle-owning wrappers (`RasterImage`, `RasterDocument`), `deinit` frees the Rust allocation. C *constants* (`RZ_FILTER_*`, …) may be used anywhere. The agent/assistant handle lifecycles belong in `RasterCore`-adjacent files, not in feature code.
- `ImageDocument.swift` — NSDocument; the single mutation point (see Undo below).
- `EditorViewController.swift`, `ImageCanvasView.swift`, `AgentServer.swift`, `Sheets.swift` — **frozen at current size.** Any change adding more than ~50 lines goes in an extension file instead: `EditorViewController+<Feature>.swift`, `AgentServer+<Feature>.swift`, or a new `…SheetController` file. A feature's MARK block is exactly the granularity that becomes a file. The pieces those extension files build on are therefore internal, not private — the editor's `document`/`canvas`/`setActiveLayer`, the server's `target`/`performGroupedEdit`/arg helpers/`jsonResult`, the sheet builders — and the frozen file keeps only the wiring (a `handlers` entry, a closure assignment, a `validateUserInterfaceItem` case).
- `Bitmap.swift` — the CoreGraphics ⇄ core-buffer seam: the ONE unpremultiply, the CGImage→straight-RGBA8 conversion, and the platform (ImageIO) decode for formats the core has none for. Anything that renders pixels with AppKit/CG converts here.
- `Tools.swift` — the single `EditorTool` enum plus per-tool facts (display name, SF Symbol, fallback glyph, cursor, bare key, selector, `planned`) as computed properties, and `railGroups`, the rail's top-to-bottom slots.
- `ToolRailView.swift` — the left tool rail; renders `railGroups`, and a group of more than one tool becomes one slot with a corner-triangle dropdown that remembers its last-used member.
- `ToolOptionsBar.swift` + `OptionControls.swift` — the fixed-height options bar: descriptor-driven (`OptionDescriptor`/`OptionCluster`), priority-ordered overflow into the `More` popover, and the 22pt control classes it builds from. Per-tool descriptor lists live in `EditorViewController+ToolOptions.swift`; persisted values in `ToolOptions.swift` (`ToolOptionsStore`). A `.field` descriptor's `quick` list (required; `[]` for none) puts a chevron menu of preset values on the field — px fields share the 1–64 `quickPx` spread, percents `quickPercent` tens, radii the doubling `quickRadius`, all defined at the top of the descriptor file.
- `AgentCatalog.swift` — the MCP tool catalog; a debug-build startup check enforces that catalog names match the dispatch registry.
- Feature model files (`TextLayer.swift`, `LayerTransform.swift`, `AdjustmentLayer.swift`, `LivePhotoLayer.swift`, `SubjectSelection.swift`, `SoftBrush.swift` are the pattern): pure value types, geometry/math, `extension RasterDocument`. `SoftBrush` is the dab engine behind the paint tools' tip options — hardness, flow, spacing, angle/roundness (`BrushTip` is the latched per-stroke value; `isStamped` decides path-vs-dabs; `BrushPreset.swift` holds the built-in preset table) — shared by the canvas stroke pipeline and the agent's stroke tools; painting blend modes route through the core's `rz_doc_painting_layer_blend`. `StrokeSpline` is the centripetal Catmull-Rom smoother the canvas stroke pipeline renders drag samples through (one sample of lag, flushed at mouse-up), and `StrokeLeash` the pulled-string stabilizer behind Smoothing; canvas only — agent strokes render the caller's exact polyline. The airbrush repeat is a main-run-loop `Timer` on the canvas (plain AppKit, not a GCD seam).
- `SubjectSelection.swift` — Vision segmentation behind Select > Select Subject and the Subject tool. The platform-model seam: it produces a canvas-sized u8 coverage mask, so it feeds `CanvasSelection(shape: .mask(…))` with no new concepts. Measured before it was written — the request is ~200 ms once (model load), 25–50 ms after, and flat in image size — so it runs synchronously on the main thread; re-measure before assuming any future Vision request may do the same. Holds all three layers of the feature: the stateless `SubjectSelection.mask` the menu and agent use, the `SubjectAnalysis` cache the tool hit-tests against (one Vision run per composite, invalidated by CGImage identity), and the `SubjectSession` gesture struct.
- `RedEye.swift` — Vision face landmarks behind Filters > Remove Red Eye and the agent's `red_eye_auto`, and the **second** platform-model seam: it turns a composite into eye discs (centre + radius) in canvas coordinates and knows nothing about pixels — the correction is the core's `red_eye_layer`. Vision's origin is bottom-left, the canvas's is top-left, so that flip is written once, in `canvasPoints`. Re-measured rather than assumed, as the bullet above says to: `VNDetectFaceLandmarksRequest` costs 79–123 ms on the first call (model load) and warm 3–5 ms at 1 MP, 11–12 ms at 12 MP, 29–30 ms at 48 MP — **not** flat in image size, unlike segmentation — plus a landmark stage of ~3 ms per face that is; so the whole automatic pass is ~35 ms warm at 48 MP and still runs synchronously on the main thread with no new queue. No repo sample holds a face Vision will find, so the detector is verified by probes only and `red_eye_auto` takes an explicit `eyes` list to drive the rest end to end.
- `AppActivity.swift` — the `NSProcessInfo` activity assertion both agent trampolines hold around a tool call. App Nap demotes an app that hogs its main thread in the background and does not undo it: measured, a 300 × 300 Content-Aware Fill is 0.75 s on a fresh app and 3.4–3.9 s for the rest of the session once one 7 s megapixel fill has run (CPU time tracks wall time, a command-line process running the same core call is unaffected, and `-NSAppSleepDisabled YES` removes it). A tool call is user-initiated work, so it says so while it runs. The UI's own long edits need no assertion — a foreground app is not napped.
- Shared chrome: `Theme.swift` (`DS` design tokens), `Controls.swift` (reusable controls), `EditorChrome.swift`; dialogs are `…SheetController`s built on the `makeSheetView` builders in `Sheets.swift`, live previews via `PreviewRenderer` (`ContentAwareFillSheetController.swift` is the current example: it hoists the selection mask once at init and the render closure captures values only, never `self`). A sheet that captures ANY input at init — the target layer, the selection's coverage bytes — must hand that same value to its commit as well as to its preview: a document-modal sheet does not stop the main run loop, so an agent's `set_active_layer` or `select_rect` can land behind it and the commit would otherwise write a layer, or fill a region, the user never saw previewed. A captured layer INDEX is not an identity — `delete_layer` renumbers everything above it and leaves the index in range, pointing at a different layer — so capture `RasterDocument.layerFingerprint` beside it and refuse at commit when the two no longer agree.

## Rules

**Placement.** New feature = small model file + VC extension file + canvas session state; the frozen four get wiring only. Interactive gestures are modeled as a session struct (`TransformSession` is the template): one stored property on the view/VC, logic in the feature's file. `PatchSession.swift` (the Patch tool's outline, then the drag that moves it — it latches the snapshot the drag previews from when the region is placed, because a preview drawn from a different image than the commit samples shows something that cannot happen) and `RedEyeSession.swift` (the Red Eye rectangle) are the newest pair. Closures assigned in `loadView` are one-line forwards to named methods (`canvas.onStrokeEnd = { [weak self] in self?.strokeDidEnd($0) }`) — no business logic in closure bodies.

**Tools.** One enum: `EditorTool` in `Tools.swift`, used by VC and canvas alike; per-tool facts live on the enum, not in scattered switches — a fact that would otherwise be a parallel list in the rail, a menu or a control belongs there. Mouse/key dispatch switches stay exhaustive with **no `default:`** so the compiler flags every site a new tool must handle. A tool's raw value is a stable order, never a rail position: the rail groups related tools onto one slot (`railGroups`, asserted to list every tool exactly once), and a group of more than one draws its current member plus a corner-triangle dropdown; the Tools menu builds itself from `railGroups`, so the menu needs no separate edit. A tool whose behavior hasn't landed ships with `planned` true: visible everywhere with a "Soon" affordance, disabled by validation. Remaining touchpoints for a new tool: enum case (+ facts), a `railGroups` slot (a new slot, or joining an existing group at no height cost), `selectXTool` action + `toolActions` entry, an options-cluster list in `EditorViewController+ToolOptions.swift` (+ a `ToolOptions.swift` family if the values persist), canvas mouse switches. Canvas point convention: positions are clamped to the canvas for most tools, deliberately unclamped for move/eyedropper/transform.

**Undo and dirty tracking.** All document mutation flows through `ImageDocument`'s entry points — `applyEdit`, `applyRasterizingEdit`, `applyToActiveLayer`, and the `beginLiveEdit`/`updateLiveEdit`/`endLiveEdit` trio for gestures. `registerUndo` appears nowhere outside `ImageDocument`. `ImageDocument` overrides `updateChangeCount` to drop AppKit's automatic undo-based counting; the entry points count deterministically via `countEditChange()` — any new edit path must go through them or the dirty flag breaks. **Pitfall:** undo registrations outside an AppKit event (agent edits, async callbacks) land in an implicit event group that never closes, silently merging edits into one undo step; any off-event path must use the explicit `beginUndoGrouping`/`endUndoGrouping` + flush pattern in `AgentServer.performGroupedEdit`.

**Agent parity.** Every user-visible edit gets an MCP mirror: a handler in the dispatch registry + a catalog entry in `AgentCatalog.swift` (the debug parity check enforces the names match) + a comment naming the UI path it mirrors. Handlers follow the canonical shape: `target(a)` → validate indices → `performGroupedEdit`/`performPixelEdit` → `jsonResult`; failures throw `ToolError` and return in-band (`isError: true`) so models can self-correct. Argument helpers (`intArg`/`doubleArg`/`boolArg`/`stringArg`) accept string forms uniformly. The UI and the agent share one selection — agent-set selections show the marquee; user selections confine agent strokes — via the two-member `agentSelection`/`agentSetSelection` surface, the only place `AgentServer` may reach into a view controller.

**State flow.** Canvas → VC through `on*` closures (`[weak self]`); panels → VC through closures or nil-target responder-chain selectors (so menus and panel buttons share handlers); document → observers via `.imageDocumentImageDidChange` with `userInfo["isLive"]` — live gestures pass `isLive: true` and observers skip expensive reloads mid-gesture. VC → canvas/panels is direct property assignment or method calls. `Selection.swift` is the shared model: geometric shapes keep an exact `NSBezierPath`; the magic wand uses a canvas-sized u8 coverage mask.

**Described layers.** A layer whose pixels are the RENDERING of something re-openable — a text layer's string, a live photo layer's frame — keeps that description in the core's opaque per-layer `meta` (one slot, so the kinds are mutually exclusive; the schema and its versioning are this side's, and an unrecognized meta degrades to a plain raster layer). The invariant is that the meta always describes the CURRENT pixels: every destructive path asks first (`ImageDocument.layerDescribesSource` / `confirmRasterize`, mirrored silently for the agent in `performPixelEdit`) and drops the meta inside the same edit. The platform rasterizes these (AppKit text layout, AVFoundation frames, ImageIO stills); the core only stores what came out.

**Hygiene.** No storyboards/xibs. No `!` force-unwraps, `as!`, or `try!`; implicitly-unwrapped optionals only for post-`loadView` view refs. Every non-NSCoder class: `@available(*, unavailable) required init?(coder:) { fatalError("<Type> does not support NSCoder") }`. `[weak self]` in retained closures, never `unowned`. Main-thread AppKit; `DispatchQueue` only at the documented seams (agent trampoline, assistant event pump, `PreviewRenderer`) — no async/await, no Combine, which is why `LivePhotoLayer.swift` uses AVFoundation's synchronous asset accessors and carries three deprecation warnings rather than an async bridge (`duration`/`tracks(withMediaType:)` since 13, `copyCGImage` since 15). Their replacements are all async, and unwinding them would make `LivePhoto.render` — and so the pure `settingLivePhotoFrame` — asynchronous; the callback form `generateCGImageAsynchronously(for:completionHandler:)` is the escape hatch if that ever becomes worth it. Colors/fonts/metrics come from `DS` tokens; shared controls go in `Controls.swift`. Refusals beep (`NSSound.beep()`), errors never crash. 4-space indent, ~100 columns.
